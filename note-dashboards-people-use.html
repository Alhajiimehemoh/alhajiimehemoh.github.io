Why dashboards fail and how to design one people use

A dashboard works when each reader sees the answer to their own question without help.

21 October 2026 · Health data · 1 min read

A dashboard is not finished when it looks good. It is finished when the person it was built for uses it to make a decision.

Start with the reader

A nurse, a programme manager and a donor ask different questions. A nurse wants to know what is due at my facility this week. A manager wants to know which facilities are falling behind. A donor wants a short summary against targets. Build a view for each, or at least decide who the main reader is.

One message per chart

If a chart needs a paragraph to explain it, split it. Give each chart a title that states the point, for example Coverage is lowest at two facilities, instead of Coverage by facility.

Show the target

A number without a target has no meaning. Add a line or colour that shows whether the result is on track.

Keep the data table underneath

People trust a chart more when they can see the numbers behind it. Keep a clean table one click away.

Make updating easy

A dashboard that takes a day to refresh will not be refreshed. Design it so a new month of data is added by dropping in the new export.

Be honest about gaps

If three facilities did not report, say so on the page. Hiding missing data makes the whole dashboard less credible.

You can try these ideas on the sample dashboard, which uses invented data.
